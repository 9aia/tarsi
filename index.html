Get started
Release semantics

Plan, don't mutate

`release` is dry-run by default — real mutation requires `dry_run: false`, the same `--yes` a human would give.

Per-unit tags

`{unit}-v{semver}` tags attribute commits by path and version each release unit independently.

Profiles as packs

Org conventions ship as `type: tarsi` tamias packs — layered config, versioned by the store.

One wire

ndjson ops over `tarsi-serve` — agents, peregrin campaigns, and humans speak the same protocol.

What it is ​

Tarsi is the org's release plane: changelog → semver bump → tag → publish, exposed as tarsi-serve ndjson ops. Repo config is tarsi.toml; org conventions ride type: tarsi tamias profile packs; there is deliberately no tarsi CLI.

Why ​

Every repo was reinventing release plumbing — changelog rendering, commit→bump inference, tag schemes, publish ordering. Tarsi makes release semantics a shared, deterministic ops surface that humans, agents, and peregrin campaigns all drive identically, with dry-run as the default so probing never mutates.

Boundary ​

  • Owns: release semantics — plans, bumps, changelogs, tags, publish orchestration.
  • Doesn't own: orchestration timing/approval (peregrin), distribution (tamias), git itself (lasius-vcs).

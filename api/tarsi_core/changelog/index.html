Changelog model: strategy-ordered sections, entries grouped under them, markdown rendering for splicing into CHANGELOG.md. Section identity/order/headings come from the release Strategy — P-030 made the keep-a-changelog section map data, so this module no longer hardcodes Section kinds; the conventional builtin reproduces the old map byte-identically.

Sections → entries for one release. sections is an ordered Vec — order is the strategy’s render order (the old BTreeMap<Section, _> relied on the enum’s declaration order; string keys can’t carry that, so the strategy’s table order is stored explicitly).

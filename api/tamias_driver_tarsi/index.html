tamias-driver-tarsi — dual-surface driver: the tamias content driver for type: tarsi release-profile packs (PL-014 D3) AND the pavo read-only view driver over tarsi release state. One binary, two consumers, disjoint argv — see tarsi_driver’s module docs for both contracts.

pavo surface (verbs take no --dir/--name):

  • manifest — print the pavo_protocol::DriverManifest JSON (discovery probe; never touches tarsi state).
  • capabilities — merged JSON advertising BOTH surfaces: pavo’s {"capabilities": ["pavo",…], "verbs": […"serve"…]} shape plus tamias’s "types": ["tarsi"] and the content verbs in verbs — one payload satisfies both discoverers.
  • serve — ndjson JSON-RPC on stdio (manifest/views/view/ query); queries ride tarsi-serve one-shot ops (plan preview, changelog preview, profile list). $TARSI_SERVE overrides the tarsi-serve binary (default: PATH).
tamias-driver-tarsi manifest|capabilities|serve
tamias-driver-tarsi <verb> --dir <d> --name <n> [--config <f>]

verb ∈ {config-schema, install, deploy, uninstall, status, health, logs, hooks}. tamias dispatches the lifecycle verbs with --dir/--name always present; the probe verbs take no flags. Every verb answers a JSON report on stdout; failures go to stderr with exit 1.

Module token 

Source
Expand description

Publish-token resolution — the seam between config’s secret names (token_env) / refs (token_ref) and the values the forges consume. Values are secret: they are never logged, never placed in error messages, and never written anywhere but the child process environment / Authorization header.

Resolution order (T-041):

  1. token_ref — an explicit cuora://<scope>/<name> secret ref, fetched through cuora-secret-cuora (audit events and vault policy apply). Nested scopes work (cuora://a/b/name → scope a/b, name name — the ref tail is the secret name).
  2. token_env — the environment variable of that name.

A cuora:// miss falls through to the env var (the org’s Secrets-chain semantics); an unsupported ref scheme is a hard config error. With no token_ref, behavior is exactly the pre-T-041 env lookup.

Env knobs follow the <PRODUCT>_CUORA_* convention: TARSI_CUORA_BIN overrides the cuora binary (tests stub it), TARSI_CUORA_TRANSPORT picks cli/serve.

CuoraTokenResolver
The default resolver: cuora:// refs via cuora-secret-cuora, env var fallback. One [CuoraSecrets] store per scope, built lazily and cached for the resolver’s lifetime (cheap under the cli transport; under serve it keeps the cuora serve child alive across lookups).

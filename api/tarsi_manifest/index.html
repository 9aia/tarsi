tarsi-manifest — the filesystem edge of unit resolution. Reads Cargo.toml (workspace members, package versions, path dependencies) and produces ReleaseUnitSpecs for tarsi_core::plan_release. Also owns manifest version writes (cargo set-version equivalent) via toml_edit so formatting/comments survive.

Pure parsing lives here; this is the only tarsi crate allowed to touch Cargo.toml files.

cargo_workspace_units
Scan <root> (a cargo workspace or single package) into ReleaseUnitSpecs — versions, paths, dep topology, and publish targets (publish = false manifests → no targets).
sync_path_dep_reqs
Rewrite version reqs on path deps so each names the target package’s current manifest version. cargo publish ships path deps with their version req — after a bump the req must match the new version (^0.1.5 rejects 0.2.0, and cargo’s own resolver fails the same way on cargo check). Run after write_unit_version writes land. Covers [workspace.dependencies] in the root manifest plus dependencies/build-dependencies/dev-dependencies in every workspace member; only entries carrying both path and a string version are touched. Returns true when any file changed.
write_unit_version
Per-unit version write that handles version.workspace = true: if the member inherits, bump the workspace version instead (only correct when all releasing units share it — callers check).
write_version
Write version into <manifest>/Cargo.toml [package], preserving the rest of the file (toml_edit). Returns true when the file changed.
write_workspace_version
Write version into [workspace.package] when members inherit it — used when every releasing unit shares one version.

tarsi-testkit — the behavioral backbone for tarsi’s ports and the tarsi-serve op surface (PL-014 B3/D5):

  • fixtures — commit-range JSON fixtures exercising every bump class; fixtures::synthetic_commits parses them into tarsi_core::commit::Commits.
  • golden — golden plan cases: specs + commits → expected bump/version/tag/changelog per unit. GoldenCase::check diffs a tarsi_core::ReleasePlan against the expectation — the spec the legacy TS behavior maps onto (B3). Cases cover synthetic ranges plus one real org range (tarsi’s own crates/tarsi-serve history).
  • repo — real-git fixture builders: temp workspace repos (multi-unit cargo workspace, bare origin, conventional commits, tags) for anything that must exercise lasius-vcs for real.
  • serve — the tarsi-serve op conformance suite: every assert_* runs one op contract against a &dyn Vcs + fixture dir, so any VCS impl (or a future serve refactor) proves the same wire behavior. serve::assert_conformance runs the read-only ops; serve::assert_release_conformance adds the mutating release path (needs origin + a no-publish tarsi.toml).

Downstream crates consume this as a dev-dependency and call the assert_* functions from their own tests — same pattern as scarab-testkit / sepia-testkit.

Modules§

fixtures
Commit-range fixtures — JSON descriptions of synthetic and real commit ranges, parsed into tarsi_core::commit::Commit for golden cases and port tests.
golden
Golden plan corpus (PL-014 B3) — specs + commit ranges → expected bump/version/tag/changelog per unit. This is the spec the legacy TS tarsi behavior maps onto: every case is data, GoldenCase::check diffs the real plan_release output against it and returns human-readable mismatches (empty = pass).
repo
Real-git fixture repos for VCS-touching tests — temp workspaces with conventional commits, tags, and a bare origin, built with the git CLI (no VCS-impl dependency, so any [lasius_vcs::Vcs] adapter can be pointed at them).
serve
tarsi-serve op conformance — the wire contract every VCS impl (and every serve refactor) must satisfy. Each assert_* drives tarsi_serve::dispatch against a caller-supplied &dyn lasius_vcs::Vcs and a fixture dir (see crate::repo); failures panic with the op + response, passes return the response value for further assertions.

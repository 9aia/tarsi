Golden plan corpus (PL-014 B3) — specs + commit ranges → expected bump/version/tag/changelog per unit. This is the spec the legacy TS tarsi behavior maps onto: every case is data, GoldenCase::check diffs the real [plan_release] output against it and returns human-readable mismatches (empty = pass).

Cases:

  • mixed-single-unit — one whole-repo unit over fixtures::SYNTHETIC_COMMITS: a breaking feat! forces major; chore/docs ride along into the changelog.
  • workspace-topo — two units with a dep edge: path-prefix attribution, per-unit bump inference, topo publish order, and the unattributed tail (repo-root files).
  • chore-only-none — docs/chore/test range → Bump::None, no release, version/tag still computed for the report.
  • real-tarsi-serve-range — the real git log range of crates/tarsi-serve between scaffold and the D3 driver commit (8 commits, newest first as a VCS port returns them).
  • real-myco-range — the real git log range of the myco repo between release tags myco-v0.1.1..myco-v0.1.2 (11 commits, whole-repo unit at path .).
  • real-tamias-core-range — the real git log range of the tamias repo between per-unit tags tamias-core-v0.1.3..tamias-core-v0.1.4 (4 commits, unit path crates/tamias-core — exercises path-prefix attribution and a release: noise commit that parses as Other).

Strategy cases (P-030) — strategy: None cases are the conventional parity gate; these exercise other strategies:

  • semantic-release-angular — the angular commit-analyzer preset as data: revert→patch joins the bump table, BREAKING CHANGES/Features/Bug Fixes/… section headings.
  • custom-deps-strategy — an inline rule table naming the arbitrary raw type deps (unreachable via CommitKind) plus a fallback bump for unmatched units.
  • keep-a-changelog — the KaC builtin: conventional bump rules + the six canonical sections; exercises every section plus the breaking-routes-to-owning-section veto.

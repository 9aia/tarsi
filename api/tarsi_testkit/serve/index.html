tarsi-serve op conformance — the wire contract every VCS impl (and every serve refactor) must satisfy. Each assert_* drives tarsi_serve::dispatch against a caller-supplied &dyn lasius_vcs::Vcs and a fixture dir (see crate::repo); failures panic with the op + response, passes return the response value for further assertions.

Two tiers:

  • assert_conformance — read-only ops: manifest, profiles, plan, changelog, notes, check, schema, plus the unknown-op error path. Safe on crate::repo::workspace_repo output as-is.
  • assert_release_conformance — the mutating release op: requires a fixture with origin (crate::repo::workspace_repo / crate::repo::single_unit_repo both provide one) and a crate::repo::NO_PUBLISH_TOML tarsi.toml written by the caller, so no forge is touched. Asserts the step order, remote branch+tag state, changelog creation, and manifest bumps.
  • assert_granular_tier — the granular ops (bump → tag → publish) chained via params.units passthrough, the node-shaped composition peregrin campaigns use. Same fixture requirements as assert_release_tier.

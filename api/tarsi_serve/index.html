tarsi-serve — the service surface. ndjson JSON-lines ops over stdin/stdout (one {"op": …, "params": …} per line, one {"ok": …}/{"error": …} response per line) — the same protocol shape as sepia serve / tamias-driver verbs.

Composition only: config via tarsi-config (scarab-config), manifests via tarsi-manifest, history/tags/push via lasius-vcs + lasius-vcs-git, planning via tarsi-core, publishing via tarsi-publish* impls. No orchestration or UI lives here — peregrin/pavo call these ops.

Op surface (PL-014 D1): read ops manifest/profiles/plan/ changelog/notes/check/schema; granular pipeline steps bump → tag → publish (each dry_run-defaulted, each echoing units for params.units chaining — the node-shaped composition peregrin campaigns drive); release stays as the composed, rollback-capable pipeline.

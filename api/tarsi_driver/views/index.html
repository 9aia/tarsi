Module views 

Source
Expand description

views — the driver’s manifest: every ViewSpec plus the query resolvers that feed them (the pavo read-only surface, PL-014 D3 remainder).

Read path: every query is one tarsi-serve one-shot op — see data.rs. plan/changelog take dir/profile/range params (--param dir=<repo>, --param profile=9aia-release, --param range=HEAD~3..HEAD on the pavo wire); absent dir means .. A failed serve call degrades to an {"error": …} payload inside an ok:true response, matching the sibling drivers’ contract — the views stay renderable with no tarsi-serve on PATH.

Surface mapping:

pavo viewtarsi-serve opdata
tarsi:statusmanifestbinary, version, ops, default dir
tarsi:profilesprofilesrelease-profile list (all roots)
tarsi:planplanrelease-plan digest + unit rows
tarsi:changelogchangelogper-unit changelog markdown

tarsi:plan answers “what would a release of dir X do?” — bumps, tags, publish-target switches, unattributed commits, ordered steps — without mutating anything (plan is read-only in the serve; release is never called).

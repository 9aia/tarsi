tarsi_driver

Module data 

Source
Expand description

data — the pavo read plane. Every query is one tarsi-serve one-shot op (tarsi-serve <op> --dir <d> --set k=v …), the same wire peregrin campaigns and humans use — the driver never opens tarsi state itself (“pavo renders what the serve reports”).

Read-only by construction: the only ops called are manifest, profiles, plan, and changelog — release is never dispatched, and plan/changelog mutate nothing (the serve’s dry_run default applies regardless).

The binary resolves as $TARSI_SERVE when set (tests and non-PATH installs point it at a specific build), else tarsi-serve on PATH — the libraries/tarsi pack deploys it under that name.
